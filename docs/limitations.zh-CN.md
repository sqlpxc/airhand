# 已知限制

[← 返回 README](../README.zh-CN.md) · [English](limitations.md)

## 通用

- 剪贴板只同步文本，不同步文件
- 声音只从被控端传到控制端，不转发控制端的麦克风；采集的是音量调节之后的声音，被控端静音时传过来的也是静音
- 会话是端到端加密的，中转服务器看不到内容，但仍然知道谁在什么时候连了谁、流量有多大（见[安全](security.zh-CN.md#端到端加密)）
- 网页控制台是端到端加密的终点：它所在的机器看得到画面
- 第一次连接一台电脑时，对方的身份是“第一次连上时记下的”（和 SSH 一样）：输入配对码（或者核对安全码）才能确定中间没有人冒充对方

## Windows

- 被控端只在控制台会话（物理屏幕）里运行：远程桌面（RDP）会话不能被控制
- 还不能发送 `Ctrl+Alt+Del`（需要 `SendSAS`）
- 调试构建在托盘进程里运行被控端，没有 SYSTEM 权限，采集和操作不了 UAC 确认框和锁屏（这期间控制端会显示采集失败）

## macOS

- 被控端需要“屏幕与系统录音”和“辅助功能”两项权限，只能由本机用户在系统设置里授予；macOS 15 起系统还会定期询问是否继续允许它录屏
- 登录界面和锁屏无法采集或操作
- 被控端不提供 AV1 编码（目前的 Apple 芯片只能硬件解码 AV1），控制台里的 AV1 会显示为不可用，自动改用 HEVC
- 控制端（WKWebView）不支持键盘锁定：全屏时 Command+Tab、Command+空格等系统快捷键仍由本机处理，请用工具栏的“发送快捷键”
- 较旧的 macOS 上 WKWebView 可能不支持 Opus 解码，这时控制台会提示无法播放远程声音

## Linux

- 被控端只支持 **X11** 桌面。Wayland 下只能看到 / 操作 X11（XWayland）程序，原生 Wayland 窗口是黑的，控制端会提示改用 X11（Xorg）会话登录。完整的 Wayland 支持需要 xdg-desktop-portal 屏幕共享（每次都要本机用户确认），尚未实现
- 被控端只有 OpenH264 软件编码（还没接 VA-API / NVENC），控制端会使用 H.264
- 锁屏无法操作（屏保程序会独占键鼠）
- 控制端的解码依赖 WebKitGTK + GStreamer：H.264 需要 `gstreamer1.0-plugins-bad`（解析）和 `gstreamer1.0-libav` 或 openh264（解码）；AV1 / HEVC 取决于装了哪些 GStreamer 解码器。某种格式实际解不出画面时，控制端会按优先级改用下一个可用的格式

## 网页控制台

- 刷新或关闭标签页会断开会话；我的设备不保存，刷新页面后清空
- Firefox 里本机剪贴板不能自动同步给对方
- 浏览器不全屏时部分快捷键（Ctrl+W 等）发不到远端

## Android

被控端（共享本机）：

- 没有配对码：没见过的控制端要么请你同意（同意请求里有安全码），要么关掉“连接前先问我”之后知道控制码就能连；同意过的控制端只在这次共享里记得
- 每次开始共享都要在手机上确认录屏（系统规定），应用被系统结束后不能自动恢复共享
- 远程操作靠无障碍服务的手势，游戏等自己处理触摸的应用可能不灵敏
- 打字只能写进普通的输入框（Android 13 以前不支持方向键、Tab）
- 锁屏（有密码时）、标了“禁止截屏”的界面是黑的
- Android 10 起应用在后台读不到剪贴板，所以只能把控制端的剪贴板同步到手机，反过来不行
- 共享声音需要 Android 10+，有的应用不允许录它的声音
- HEVC 和 AV1 只在手机有对应的**硬件**编码器时提供（有 AV1 硬件编码器的手机还很少），否则用 H.264（没有硬件 H.264 编码器时用系统的软件编码器）

控制端：

- 同一时间只连一台；没有音画同步；电视上只看不操作
- HEVC 和 AV1 只在本机有对应的**硬件**解码器时使用，否则用 H.264

AV1（编码和解码）还没有在真机上验证过：模拟器没有 AV1 硬件编解码器。
