# 已知限制

[← 返回 README](../README.zh-CN.md) · [English](limitations.md)

## 通用

- 剪贴板传文件（见[工作原理 → 剪贴板里的文件](architecture.zh-CN.md#剪贴板里的文件)）：只能走中转时，一次粘贴最多传服务器允许的大小（`AIRHAND_MAX_FILE_SIZE`，默认 50 MiB），直连通着时不限。复制之后又改过的文件取不了（大小、修改时间对不上），要重新复制。文件夹里的链接只重建相对路径、不出这个文件夹的，而且只有 Linux 接收时重建，别的平台跳过。没有总进度：进度条是接收方的文件管理器自己的
- 采集的是被控端音量调节之后的声音，被控端静音时传过来的也是静音
- 麦克风转发需要 Windows 的 Steam Streaming Microphone（已有设备或从本机 Steam 安装）、macOS 14.2+ 或 Linux 用户会话里的 PipeWire 0.3.49+。Android 被控端和 Android 原生控制端还不支持。
- 会话是端到端加密的，中转服务器看不到内容，但仍然知道谁在什么时候连了谁、流量有多大，画面每帧一条流时还看得出每一帧有多大（见[安全](security.zh-CN.md#端到端加密)）
- 网页控制台是端到端加密的终点：它所在的机器看得到画面
- 第一次连接一台电脑时，对方的身份是“第一次连上时记下的”（和 SSH 一样）：输入配对码（或者核对安全码）才能确定中间没有人冒充对方
- 直连只靠打洞：两端都在对称 NAT（常见于部分运营商的大内网、公司网络）后面、又不是都有公网 IPv6，或者防火墙挡了 UDP 时打不通，一直走中转；没有 UPnP / NAT-PMP 端口映射。直连突然断了（例如被控端换了网络）时画面会停顿约一秒（被控端发现之后改回中转、编一个关键帧），之后才再试直连
- 控制通道在直连通着时两条路都发（中转上始终有完整的一份），大块通道（剪贴板、光标图像）只走中转：中转服务器上的流量少了画面和声音，但不是零
- 丢帧时从长期参考帧恢复（不用编关键帧）目前只有 Windows 的硬件编码器能做：H.264（NVIDIA、Intel）和 NVIDIA 的 AV1。HEVC、macOS（VideoToolbox）、Linux 和软件编码（OpenH264）、Android（MediaCodec）恢复时编关键帧（见[工作原理 → 帧流与参考帧失效](architecture.zh-CN.md#帧流与参考帧失效)）
- 画面每帧一条流要中转服务器也是 v10：旧的服务器照样能用，只是画面还是一条流，丢一个包就挡住后面的帧
- 同时显示几个显示器时（见[使用说明 → 多屏](usage.zh-CN.md#多屏)）最多 4 个；每个显示器各自采集、编码，被控端的编码开销和带宽大致按显示器的个数翻倍（画质设置对每一个分别生效）；显卡同时开不了那么多硬件编码器时，多出来的那几路退回软件编码。音画同步对所有的一起推迟。Android 被控端只有一块屏幕，Android 控制端一次只看对方的一个显示器
- 独立帧流允许后面的帧先到。依赖丢失参考帧的增量帧仍需等待重传或恢复，因此长往返、高丢包链路可能卡顿。

## Windows

- 被控端只在控制台会话（物理屏幕）里运行：远程桌面（RDP）会话不能被控制
- 还不能发送 `Ctrl+Alt+Del`（需要 `SendSAS`）
- 粘贴对方复制的文件夹时，从这个文件夹算起超过 259 个字符的路径（Windows 的虚拟文件的限制）和文件夹里的链接都跳过（日志里有记录，界面上没有提示）。被控端在系统服务里时，复制、粘贴文件要靠托盘（以登录的用户的身份读写）：托盘退出了就只同步文本
- 调试构建在托盘进程里运行被控端，没有 SYSTEM 权限，采集和操作不了 UAC 确认框和锁屏（这期间控制端会显示采集失败）
- [虚拟显示器](usage.zh-CN.md#虚拟显示器)（显示器关了电源也能控制、防窥模式）只在为所有用户安装、装了随包的虚拟显示器驱动（MttVDD）时可用。驱动的签名是 SignPath Foundation 的，不是微软的：安装时 Windows 会确认一次；Windows 11 ARM64 只认微软签名的驱动，装不上。这台电脑上已经有别的程序（例如 Sunshine）装的 Virtual Display Driver 时 Airhand 不用它
- 换到虚拟显示器、换回来都要启用 / 停用设备、改显示设置，画面会停几秒；窗口跟着挪到虚拟显示器上，换回来时 Windows 按它记着的设置把显示器放回去，窗口的位置不一定和原来一样。虚拟显示器不支持 HDR
- 防窥模式挡不住本机按 Ctrl+Alt+Del（只是切到安全桌面，本机的显示器上也看不到），也挡不住合盖、按电源键让电脑睡眠；本机的声音照样从本机的扬声器放出来（被控端采集的就是它）。控制端还连着的时候，本机的人要结束它只能断开网络（会话断开之后按一下键盘）或者重启电脑
- 有会话时保持亮屏、不睡眠靠的是电源请求：合盖、按电源键这些用户自己让电脑睡眠的挡不住；支持现代待机的电脑用电池时，系统会在睡眠超时 5 分钟后终止这些请求
- 控制端的麦克风写进 Steam Streaming Microphone 时：它的两个设备（声音设置里的“扬声器”和“麦克风”）默认格式不一样的话（常见），用独占模式写：控制端打开麦克风期间 Steam 远程同乐用不了它，反过来也一样；声音设置里关掉了“允许应用程序独占控制该设备”时打不开（把两个设备的默认格式调成一样就不用独占了）。不会自动把它设为默认录音设备：在程序里选，或者自己在声音设置里设

## macOS

- 在 Mac 上用 Safari 网页录音时，选中 **Airhand Microphone** 后要关闭**网页里的回声消除**。Safari 27.2 开启回声消除时会在启动语音采集时拒绝这个虚拟设备。开发网页时可以用 `echoCancellation: { exact: false }` 和选中的 `deviceId` 重新请求麦克风。
- 被控端需要“屏幕与系统录音”和“辅助功能”两项权限，只能由本机用户在系统设置里授予；macOS 15 起系统还会定期询问是否继续允许它录屏
- 登录界面（重启之后还没有人登录时）无法采集或操作。锁屏可以：屏幕熄了的话，控制端连上来时叫醒它
- 睡眠的 Mac 离线、连不上。**不自动睡眠**（见[使用说明 → 被控端](usage.zh-CN.md#被控端默认)的“锁屏和睡眠”）只在 Airhand 运行、接着电源时生效（这时合上盖子也不睡），苹果菜单里选“睡眠”、用电池时合上盖子、电量低挡不住；睡着了之后 Airhand 也没法从远处叫醒它。合上盖子只在接着电源时能接着控制，而且虚拟显示器要在合盖之前就在（远程控制时，或者开着**不自动睡眠**时一直都在）；补上的虚拟显示器用的是 macOS 的私有接口（`CGVirtualDisplay`，DeskPad、BetterDisplay 用的也是它），以后的 macOS 改了它的话就补不上，打开盖子之前控制端看到的是“没有显示器”
- 防窥模式（Mac）是把显示器调成全黑（gamma 表），背光还亮着；系统在插拔显示器、唤醒时会把 gamma 表恢复，Airhand 0.1 秒内再调黑，中间可能闪一下。M5 Pro / M5 Max、MacBook Neo 上的 macOS 26 收下调过的 gamma 表却不显示（苹果的问题），AirPlay、随航（iPad）、DisplayLink 的显示器没有 gamma 表：这些显示器只靠盖在最上面的黑窗口挡着，鼠标指针挡不住，锁屏界面也可能露出来。挡不住本机在有焦点的密码框里打字（macOS 的“安全输入”：这时键盘事件不经过 Airhand），也挡不住电源键、合盖；只挡键盘、鼠标、触控板这些硬件来的输入，本机别的程序合成的键盘鼠标事件不挡。本机的声音照样从本机的扬声器放出来
- 被控端不提供 AV1 编码（目前的 Apple 芯片只能硬件解码 AV1），控制台里的 AV1 会显示为不可用，自动改用 HEVC
- 控制端（WKWebView）不支持键盘锁定：全屏时 Command+Tab、Command+空格等系统快捷键仍由本机处理，请用工具栏的“发送快捷键”
- 较旧的 macOS 上 WKWebView 可能不支持 Opus 解码，这时控制台会提示无法播放远程声音
- Mac 通过菜单栏的 **Airhand → 接收文件到…** 接收对方复制的文件和文件夹。访达的粘贴键只操作 Mac 自己的剪贴板。

## Linux

- 被控端只支持 **X11** 桌面。Wayland 下只能看到 / 操作 X11（XWayland）程序，原生 Wayland 窗口是黑的，控制端会提示改用 X11（Xorg）会话登录。完整的 Wayland 支持需要 xdg-desktop-portal 屏幕共享（每次都要本机用户确认），尚未实现
- 被控端只有 OpenH264 软件编码（还没接 VA-API / NVENC），控制端会使用 H.264
- 锁屏无法操作（屏保程序会独占键鼠）
- 接收对方复制的文件要 FUSE（`fusermount3` 和 `/dev/fuse`）：没有的话（例如在容器里）只同步文本。剪贴板用的是 X11 的 CLIPBOARD，原生 Wayland 程序要经 XWayland 才看得到
- 控制端的解码依赖 WebKitGTK + GStreamer：H.264 需要 `gstreamer1.0-plugins-bad`（解析）和 `gstreamer1.0-libav` 或 openh264（解码）；AV1 / HEVC 取决于装了哪些 GStreamer 解码器。某种格式实际解不出画面时，控制端会按优先级改用下一个可用的格式

## 网页控制台

- 刷新或关闭标签页会断开会话；我的设备不保存，刷新页面后清空
- Firefox 里本机剪贴板不能自动同步给对方
- 本机的文件要在画面上按粘贴键、或者拖到画面上才发给对方（网页读不了剪贴板里的文件）。对方复制的文件不进本机剪贴板，要点“下载”：Chrome / Edge 存进选的文件夹，别的浏览器在内存里拼好（几个文件、文件夹时打成 ZIP）再下载，最多 1 GiB
- 浏览器不全屏时部分快捷键（Ctrl+W 等）发不到远端

## Android

被控端（共享本机）：

- 配对过的设备连上来不用手机前的人确认（每次都会弹通知提醒）。配对过的设备只能全部忘掉（“共享本机”页或设置里），不能单独忘掉某一台
- 每次开始共享都要在手机上确认录屏（系统规定），应用被系统结束后不能自动恢复共享
- 远程操作靠无障碍服务的手势，游戏等自己处理触摸的应用可能不灵敏
- 打字只能写进普通的输入框（Android 13 以前不支持方向键、Tab）
- 锁屏（有密码时）、标了“禁止截屏”的界面是黑的
- Android 10 起应用在后台读不到剪贴板，所以只能把控制端的剪贴板同步到手机，反过来不行
- 手机上的文件要用系统的分享菜单“发给对方”才能粘贴到对方那里（只有文件，分享菜单给不了文件夹）。对方复制的文件夹进不了手机的剪贴板，只能在通知里保存到下载；Android 9 及更早保存在应用自己的目录里（`Android/data/<应用>/files/Download/Airhand`）。Android 7 上别的应用只能从头到尾读对方的文件，不能跳着读
- 共享声音需要 Android 10+，有的应用不允许录它的声音
- HEVC 和 AV1 只在手机有对应的**硬件**编码器时提供（有 AV1 硬件编码器的手机还很少），否则用 H.264（没有硬件 H.264 编码器时用系统的软件编码器）

控制端：

- 同一时间只连一台；没有音画同步；电视上只看不操作
- 传文件时没有前台服务：应用退到后台久了，系统可能停掉它，传到一半的文件就断了
- HEVC 和 AV1 只在本机有对应的**硬件**解码器时使用，否则用 H.264

AV1（编码和解码）还没有在真机上验证过：模拟器没有 AV1 硬件编解码器。
