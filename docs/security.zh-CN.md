# 安全

[← 返回 README](../README.zh-CN.md) · [English](security.md)

- 全程 TLS 1.3（QUIC），客户端用**证书指纹固定**校验服务器。没有配置指纹时，第一次连上服务器时记住它的证书（首次使用时信任：桌面版记在 `config.toml` 的 `[server_trust]` 里，Android 记在设置里，网页控制台是 `server-trust.txt`），之后证书变了就拒绝连接
- 防暴力猜码：同一个 IP（IPv6 按 /64 合并）10 分钟内最多失败 20 次，每次失败额外延迟 400 ms
- 注册不能用来探测控制码：取回控制码要出示服务器为**这个控制码**签发的密钥（用服务器自己的密钥签名，存在 `airhand.db` 里，服务器重启之后也认得）。拿不出来就分配一个新的，不管要的那个控制码有没有人用。新分配的控制码按网络限量（同一个 IPv4 地址 / IPv6 的 /48 每 10 分钟 30 个，`AIRHAND_NEW_CODES_PER_IP`），不能批量占用控制码
- 重连凭证：连上被控端时服务器给控制端一个凭证（由被控端的控制码和密钥算出，算不出也反推不出密钥），重连时带上。带凭证的请求不算失败、不受限速影响，所以被控端离线再久，控制端的自动重连也不会把自己（或者共用一个 IP 的网页控制台）锁住；凭证不对时服务器一律回答“不在线”，不透露控制码是否存在，凭证不能用来猜码。被控端换了控制码、或者被控端的用户**断开所有控制端**时（服务器随即给被控端换一个密钥），旧凭证都作废：被断开的控制端不能带着凭证马上连回来，得重新输入控制码
- 重连后取回控制码需要随机密钥，别人无法冒领
- 服务器资源：同一个 IP（IPv6 按 /64）同时最多 128 条连接（`AIRHAND_MAX_CONNS_PER_IP`）；中转的 QUIC 流控窗口按转发来定（每条流 4 MiB、每条连接 16 MiB），不读数据的一方最多让服务器替它缓存几 MiB
- 固定的控制码：服务器只保存被控端密钥的哈希（在 `airhand.db` 里），拿到数据库也冒领不了控制码。Windows 上被控端的密钥用 SYSTEM 账户的 DPAPI 加密，把 `config.toml` 拷到别的电脑上也带不走控制码；macOS / Linux 上 `config.toml` 只有本账户能读写。**更换控制码**时服务器上的旧码随即释放
- 我的设备里保存着别的电脑的控制码：Windows 上用你的账户加密（DPAPI），macOS / Linux 靠文件权限（600）。不要把 `config.toml` 发给别人
- Windows 被控端以 SYSTEM 身份运行，才能操作 UAC 确认框和登录界面：拿到控制码的人就能以管理员权限控制这台电脑。只把控制码告诉信任的人；坐在电脑前的人随时能看到谁连着、断开他们、更换控制码或者退出 Airhand
- 被控端在托盘里随时能看到谁在控制本机，可以一键断开或更换控制码
- 中转服务器能看到会话流的内容（TLS 在服务器终止），请部署在你信任的机器上
- 网页控制台：WebSocket 只接受同一个网站的页面（防止别的网站在你的浏览器里偷偷连上来）；可以设置访问密码（HTTP Basic 登录，之后是 HttpOnly、SameSite=Strict 的 Cookie，密码错误时延迟回应）；从其它电脑访问请用 HTTPS。网页控制台同样能看到画面，请部署在你信任的机器上。所有人都通过这台机器的 IP 连中转服务器，防暴力猜码的额度也是大家共用的
