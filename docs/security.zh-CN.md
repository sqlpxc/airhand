## 中转服务器和控制码

- 全程 TLS 1.3（QUIC），客户端用**证书指纹固定**校验服务器。没有配置指纹时，第一次连上服务器时记住它的证书（首次使用时信任：桌面版记在 `config.toml` 的 `[server_trust]` 里，Android 记在设置里，网页控制台是 `server-trust.txt`），之后证书变了就拒绝连接
- 防暴力猜码：同一个 IP（IPv6 按 /64 合并）10 分钟内最多失败 20 次，每次失败额外延迟 400 ms。控制码存在、但被控端还没准备好（正在注册、正在断开）时的回答和控制码不存在时一模一样（一样算失败、一样延迟），不能靠回答的快慢看出控制码是否存在
- 控制码对了也限速：每个连接请求都占着被控端的一个会话名额，手机还要弹一次连接请求，所以同一个 IP（IPv6 按 /64 合并）一分钟内最多向同一台被控端发起 6 次连接（`AIRHAND_CONNECTS_PER_MINUTE`，带重连凭证的也算）；手机上同时最多有 2 个请求在等你回答，再来的直接回绝。有人拿着控制码反复骚扰时，**更换控制码**
- 注册不能用来探测控制码：取回控制码要出示服务器为**这个控制码**签发的密钥（用服务器自己的密钥签名，存在 `airhand.db` 里，服务器重启之后也认得）。拿不出来就分配一个新的，不管要的那个控制码有没有人用。新分配的控制码按网络限量（同一个 IPv4 地址 / IPv6 的 /48 每 10 分钟 30 个，`AIRHAND_NEW_CODES_PER_IP`），不能批量占用控制码
- 重连凭证：连上被控端时服务器给控制端一个凭证，重连时带上。凭证的前一半是服务器用自己的密钥给控制码签的名（证明拿着它的控制端连上过这个控制码），后一半由被控端的控制码和密钥算出（算不出也反推不出密钥）。带凭证的请求不算失败、不受猜码限速的影响，所以被控端离线再久，控制端的自动重连、从我的设备打开一台不在线的设备，都不会占用这个 IP（或者共用一个 IP 的网页控制台）的猜码额度；不是服务器为这个控制码发的凭证，不管控制码在不在、有没有人用都是同一个回答，凭证不能用来猜码。被控端换了控制码、或者被控端的用户**断开所有控制端**时（服务器随即给被控端换一个密钥），旧凭证都作废：被断开的控制端不能带着凭证马上连回来，得重新输入控制码。被控端换密钥时断线、没收到新密钥的话，下次注册时请服务器顺便换（服务器那时可能已经重启、什么都不记得了），旧密钥不会重新生效、旧凭证也不会跟着恢复
- 重连后取回控制码需要随机密钥，别人无法冒领
- 服务器资源：同一个 IP（IPv6 按 /64）同时最多 128 条连接（`AIRHAND_MAX_CONNS_PER_IP`）；中转的 QUIC 流控窗口按转发来定（每条流 4 MiB、每条连接 16 MiB），不读数据的一方最多让服务器替它缓存几 MiB
- 固定的控制码：服务器只保存被控端密钥的哈希（在 `airhand.db` 里），拿到数据库也冒领不了控制码。Windows 上被控端的密钥用 SYSTEM 账户的 DPAPI 加密，把 `config.toml` 拷到别的电脑上也带不走控制码；macOS / Linux 上 `config.toml` 只有本账户能读写。**更换控制码**时服务器上的旧码随即释放
- 我的设备里保存着别的电脑的控制码：Windows 上用你的账户加密（DPAPI），macOS / Linux 靠文件权限（600）。不要把 `config.toml` 发给别人
- Windows 被控端以 SYSTEM 身份运行，才能操作 UAC 确认框和登录界面：能连上它的人（知道控制码，并且配对过或者知道配对码）就能以管理员权限控制这台电脑。只把控制码和配对码告诉信任的人；坐在电脑前的人随时能看到谁连着、断开他们、更换控制码 / 配对码或者退出 Airhand
- 被控端在托盘里随时能看到谁在控制本机，可以一键断开或更换控制码

## 端到端加密

和中转服务器之间的 TLS 在服务器终止，所以会话还要再加一层端到端加密（协议见 `crates/airhand-proto/src/handshake.rs`）：

- **看不到、改不了**：每个会话开始时，控制端和被控端在控制通道上做 Noise 握手（X25519、ChaCha20-Poly1305、BLAKE2s），之后画面、声音、键盘鼠标、剪贴板都是端到端加密的（AES-256-GCM），每条通道每个方向各用一把密钥，每一帧都带着编号（控制、大块通道上必须一个接一个）。中转服务器看不到内容，改了、丢了、重放、插入的帧都解不开，会话随之断开。会话版本和能力位也在加密的握手里协商，服务器没法让两端降级；没有不加密的会话可以退回去
- **认得出对方**：每台设备有一对长期密钥。控制端第一次连上一台电脑时记下它的公钥（我的设备里的 `host_key`，和 SSH 的 known_hosts 一样），之后只认它。对不上时提示“对方的身份变了”，不自动重连，也不能一点就信任新的身份：这个提示是握手完成之前的明文，中转服务器也伪造得出来，要是一点就不验证地重新记下对方，服务器随时能让你把它自己当成那台电脑记下来。确认对方确实重装过之后（也可能是有人在冒充它），输入对方托盘里现在的配对码**重新配对**：配对码认的是对方，配对成功才记下新的身份。对方是手机（没有配对码）的话，在我的设备里删掉它再连。第一次连接时两边显示同一个 6 位**安全码**（控制台：鼠标停在工具栏的控制码上；被控端：托盘里正在控制本机的设备后面；手机：同意请求里），对一下就能确认中间没有人
- **配对码**：控制码是中转服务器分配、用来找到被控端的，**服务器知道所有控制码**，只凭控制码放行就等于信任服务器（它自己就能连上来）。所以桌面被控端默认要求**配对码**：没配对过的控制端第一次连接时，要输入被控端托盘菜单里的 6 位配对码。配对码从不经过服务器，双方用 SPAKE2 把它换成密钥（配对码只有几位数，直接拿来当密钥的话，中间人拿到一次握手的记录就能离线试出来；用 SPAKE2 每次尝试只能猜一次）。连续 5 次未完成配对（输错、握手中断或超时）后暂停配对，要本机用户在托盘里换一个配对码才恢复。握手开始时就占用本机名额，失败次数加上在途尝试最多为 5；换码或忘掉配对设备后，旧握手不能再提交授权。配对之后被控端记住这个控制端（`config.toml` 的 `[[paired]]`），以后不用再输
- **重放**：重连记得的电脑只要一个往返（Noise IK），这种握手的第一条消息没有新鲜性，中转服务器可以把录下来的再发一次。被控端会回答它、开始采集（不等确认，省一个往返），但要解开控制端的第一帧密文（确认）之后才在托盘、手机的列表里显示它、才请本机用户同意，10 秒等不到就结束，而这一帧只有真正的控制端发得出来；画面用的会话密钥重放的一方也算不出来。所以重放没法让被控端显示一个并不在连的已配对控制端，也拿不到任何内容，最多让被控端白编码几秒
- 托盘菜单里可以**更换配对码**、**忘掉已配对的控制端**；**更换控制码**时两样都做。`config.toml` 里写 `access = "open"` 就不要配对码：知道控制码就能连，等于信任中转服务器
- Android 被控端不用配对码，默认请手机前的人同意（同意请求里有安全码）。同意过的控制端在这次共享里重连不再问，认的是它在加密握手里的公钥，服务器冒充不了。关掉“连接前先问我”就等于信任中转服务器
- 密钥保存在哪里：被控端的身份和配对码在 `config.toml` 的 `[host]`（Windows 用 SYSTEM 账户的 DPAPI 加密）；控制台的身份在 `[controller]`（Windows 上每个账户一把，用这个账户的 DPAPI 加密）；Android 在应用的私有目录里；网页控制台在 `controller-key.txt`（`AIRHAND_WEB_IDENTITY`）
- 中转服务器仍然知道的：谁在什么时候连了谁（控制码、IP、双方报的名称和系统），以及流量的大小和时间（打字的节奏可能从流量的时间上看出来）
- **直连**（见[工作原理](architecture.zh-CN.md#直连)）：直连上跑的是同样的端到端密文，安全性和经过中转时一样。对面是谁由 TLS 双向认证确认：两端各有一张临时生成的证书，指纹在加密、认证过的控制通道上交换，TLS 只认这两个指纹，中间人冒充不了任何一边。控制通道在中转上始终有完整的一份，计数照样必须一个接一个，直连上丢掉、晚到的帧不影响什么。直连需要两端知道对方的 IP 地址：服务器只告诉每一端它自己的公网地址，候选地址（包括局域网地址）在加密的控制通道上交换，被控端在会话开始之后（本机用户同意了之后）才发；所以只知道控制码、还没被放进来的人拿不到被控端的地址，中转服务器也看不到局域网地址。被控端只在有会话在发候选地址时才接受直连的握手
- 桌面控制台：控制台窗口经一条只监听 127.0.0.1 的 WebSocket 连程序里的控制端服务。地址里带着随机令牌，只有控制台页面拿得到（Tauri 命令），并且只接受控制台页面的 Origin，本机的其它程序、浏览器里的网页都连不上来。上面跑的是已经解密的画面，不出这台电脑
- 网页控制台：端到端加密的终点是网页控制台的服务（它才是控制端），浏览器到它是 HTTPS / WSS。所以网页控制台所在的机器看得到画面；它和中转服务器在同一台机器上时，网页控制台的用户等于没有端到端加密

## 网页控制台

- WebSocket 只接受同一个网站的页面（防止别的网站在你的浏览器里偷偷连上来）；可以设置访问密码（HTTP Basic 登录，之后是 HttpOnly、SameSite=Strict 的 Cookie，密码错误时延迟回应）；从其它电脑访问请用 HTTPS。网页控制台同样能看到画面，请部署在你信任的机器上。所有人都通过这台机器的 IP 连中转服务器，防暴力猜码的额度也是大家共用的
